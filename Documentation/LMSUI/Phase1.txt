# LMS.Web Frontend Architecture Guide

## Version 1.0

---

# Project Vision

The ASP.NET Core API is the heart of the system.

It already contains:

* Authentication
* Authorization
* Business Logic
* Validation
* Services
* Repositories
* Entity Framework
* SQL Server

The MVC project **must never duplicate this logic.**

The MVC project is only responsible for displaying data and interacting with the API.

---

# Architecture

```text
Browser

      ▼

      ▼
```

# Responsibilities

## API Project

Responsible for

* Authentication
* Authorization
* CRUD
* Validation
* Business Rules
* SQL Server
* File Uploads
* Emails
* Notifications
* Payments

Nothing from the API should be rewritten inside MVC.

---

## MVC Project

Responsible for

* Routing
* Layout
* Loading Pages
* Loading HTML Components
* Loading JavaScript

Nothing more.

---

## JavaScript

Responsible for

* Calling APIs
* Rendering HTML
* Handling Events
* Form Validation
* Dynamic Updates
* Notifications
* Loading Components

# Current Folder Structure

```
Controllers

wwwroot

    assets

    html

```

---

# Controllers

Controllers only return Views.

Example

```csharp
public IActionResult Index()
{
    return View();
}
```

Controllers never call SQL Server.

Controllers never contain business logic.

---

# Views

Views are only shells.

Example

```html
<div id="page-content"></div>

@section Scripts{

<script src="~/js/features/course/index.js"></script>

}
```

Views never contain large HTML templates.

Views never call APIs.

Views never contain JavaScript logic.

---

# HTML Components

The Histudy template becomes reusable HTML components.

Example

```
html

    header.html

    footer.html

    sidebar.html

    topbar.html

    loader.html

    breadcrumb.html

home

course

student

instructor

dashboard

account
```

Each component should remain independent.

# JavaScript Framework

The JavaScript folder is divided into three areas.

```
js

```

---

# Core Folder

```
core

app.js

config.js

api-client.js

component-loader.js

auth.js

storage.js

utilities.js

router.js
```

These files are written once and reused throughout the application.

---

## app.js

Application entry point.

Responsible for

* Starting the application
* Initializing shared components
* Loading page modules

---

## config.js

Contains global configuration.

Example

* API URL
* Version
* Environment
* Timeouts

No hard-coded URLs anywhere else.

---

## api-client.js

One place for every HTTP request.

Instead of calling

$.ajax()

throughout the application,

every request goes through

* get()
* post()
* put()
* delete()

This gives one consistent API client.

---

## component-loader.js

Responsible for loading reusable HTML.

Example

Header

Footer

Sidebar

Topbar

Breadcrumb

Modals

No duplicated loading logic.

---

## auth.js

Responsible for

* Login
* Logout
* JWT
* Refresh Token
* Authorization Header

Authentication logic exists only here.

---

## storage.js

Responsible for

* Local Storage
* Session Storage
* Current User
* Remember Me

No direct localStorage usage anywhere else.

---

## utilities.js

Contains helper methods.

Examples

* Date Formatting
* Currency Formatting
* Validation
* Loading Spinner
* Toast Notifications

Shared by the entire application.

---

## router.js

Responsible for page initialization.

Determines which feature script should start.

# Feature Responsibilities

## api.js

Only communicates with ASP.NET Core API.

No HTML.

No DOM manipulation.

---

## service.js

Processes data.

Examples

* Filtering
* Sorting
* Mapping
* Calculations

No UI logic.

---

## ui.js

Responsible for

* Rendering HTML
* Updating DOM
* Showing Cards
* Showing Tables
* Showing Modals

No API calls.

---

## events.js

Responsible for

* Button Clicks
* Search
* Pagination
* Filters
* Keyboard Events

Only event handling.

---

## index.js

Feature entry point.

Responsible for

* Initializing page
* Registering events
* Loading initial data

---

# HTML Strategy

Never create large HTML strings inside JavaScript.

Instead use HTML components.

Example

```
course

course-card.html

course-detail.html

review.html

curriculum.html
```

JavaScript only fills the data.

HTML remains clean.

---

# Layout Strategy

The Layout page contains only placeholders.

Example

```
Header

RenderBody()

Footer

Scripts
```

The actual HTML is loaded dynamically by the Component Loader.
