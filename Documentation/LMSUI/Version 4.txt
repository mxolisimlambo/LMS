LMS.Web Frontend Development Guide
Version 1.3

Author: Mxolisi Goodman

1. Project Overview

The LMS.Web frontend now follows a fully modular, API-driven JavaScript architecture.

The core framework has been completed and standardized before Dashboard development begins.

Every feature in the application must follow the same architecture.

The objective is to build an enterprise-grade frontend that is:

Modular
Reusable
API Driven
Permission Driven
Secure
Easy to Maintain
Easy for New Developers to Understand

Responsible for global application configuration.

AppConfig.appName

ApiClient

Responsible for all HTTP communication.

Supported methods

ApiClient.get()

ApiClient.post()

ApiClient.put()

ApiClient.patch()

ApiClient.delete()

ApiClient.upload()

ApiClient.download()

Features

Automatic JWT token attachment
Global error handling
401 detection
403 detection
404 detection
500 detection
File upload support
File download support

Business modules never use jQuery AJAX directly.

Supported methods

StorageService.get()

StorageService.setAccessToken()

StorageService.getAccessToken()

StorageService.removeAccessToken()

StorageService.setRefreshToken()

StorageService.getRefreshToken()

Responsible for authentication and authorization.

Supported methods

SecurityService.redirectIfUnauthorized()

14. Development Rules
Never call APIs directly from page files.
Never manipulate HTML inside Service classes.
Never access localStorage directly.
Always use StorageService.
Always use SecurityService for authentication.
Always use ApiClient for HTTP communication.
Always register pages with PageRegistry.
Always initialize through app.js.
Never use $(document).ready() inside page modules.
Never duplicate shared HTML.
