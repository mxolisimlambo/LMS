# Online Learning Management System (LMS)

## MVC Frontend Architecture Plan

### Project Goal

The backend (ASP.NET Core Web API) is already complete and contains all business logic.

The MVC project **will not contain business logic**. It will act as a Presentation Layer that:

* Hosts the HTML template
* Loads JavaScript
* Calls the ASP.NET Core API
* Renders data returned by the API

The MVC project becomes a lightweight UI application.

# Responsibilities

## ASP.NET Core API

Responsible for:

* Authentication
* Authorization
* CRUD Operations
* Validation
* Business Rules
* Database Access
* File Uploads
* Payments
* Reports

The API is the only source of business logic.

---

## ASP.NET Core MVC

Responsible for:

* Routing
* Authentication Cookies (if applicable)
* Loading Views
* Serving Static Files
* Loading JavaScript
* Loading HTML Components

No database access.

No repositories.

No services.

No Entity Framework.

No business logic.

---

## JavaScript

Responsible for:

* Calling APIs
* Rendering HTML
* Handling Events
* Validation
* UI Updates
* Dynamic Components

# Feature Folder Structure

Example:

```text
course

api.js

service.js

ui.js

events.js

index.js
```

Each file has one responsibility.

---

## api.js

Responsible for communicating with the backend.

Example methods:

* getAll()
* getById()
* create()
* update()
* delete()
* search()

No HTML.

No DOM manipulation.

---

## service.js

Responsible for preparing API data.

Example:

* sorting
* filtering
* mapping
* formatting

No HTML.

---

## ui.js

Responsible for:

* Rendering HTML
* Updating DOM
* Showing Modals
* Showing Notifications

Only UI logic.

---

## events.js

Responsible for:

* Button Clicks
* Search
* Filters
* Pagination
* Keyboard Events

Only event handling.

---

## index.js

Responsible for initializing the page.

Example:

* Load Components
* Register Events
* Load Initial Data

---

# HTML Components

Never build long HTML strings inside JavaScript.

Instead use reusable HTML templates.

Example:

```text
html

course

course-card.html

course-filter.html

course-detail.html

review.html
```

JavaScript loads the template.

Populates it.

Displays it.

---

# Shared Components

```text
shared

header.html

footer.html

sidebar.html

topbar.html

loader.html

modal.html
```

These components are reused throughout the application.

---

# Component Loader

Create one reusable loader responsible for loading HTML components.

Responsibilities:

* Load HTML
* Insert HTML
* Initialize Components

Every page should use the same loader.

---

# API Communication

JavaScript never calls $.ajax() directly throughout the project.

Instead every API is wrapped.

Example:

Course API

↓

Course Service

↓

Course UI

↓

Course Events

↓

Course Page

This keeps responsibilities separated.

# Advantages

* Single source of business logic (API)
* Lightweight MVC project
* Reusable HTML components
* Small Razor Views
* Feature-based JavaScript
* Easier maintenance
* Easier testing
* Easier scaling
* Mobile applications can reuse the same API
* Cleaner separation of concerns

# Development Strategy

For every new module, follow the same pattern.

Example: Course Module

1. Create MVC Controller.
2. Create Razor View (Shell).
3. Create HTML Components.
4. Create Feature JavaScript Folder.
5. Create API Wrapper.
6. Create Service.
7. Create UI Renderer.
8. Create Event Handlers.
9. Initialize from index.js.
10. Connect to ASP.NET Core API.

Every module in the LMS (Courses, Students, Instructors, Lessons, Quizzes, Payments, Certificates, Reviews, Enrollments, Dashboard, etc.) should follow this identical structure to keep the frontend consistent, scalable, and easy to maintain.
